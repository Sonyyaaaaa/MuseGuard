# MuseGuard: вимоги до проєкту

## Ідея

MuseGuard допомагає працівнику музею стежити за вітриною з експонатом. Система має окремо показувати присутність людини поруч, зміну освітлення та механічний вплив на корпус. Ці спостереження можуть потребувати перевірки, але самі по собі не встановлюють намір людини чи факт крадіжки.

Прототип працює без фізичної плати, у Wokwi на STM32 HAL. ЛР1 підготувала збірку, UART/LED та вимоги. ЛР2 додає сенсори, драйвери, спільне опитування, signal captures та тести.

## Функціональні вимоги

- **FR-01.** Після запуску система повинна повідомити через UART модель і поточний стан та періодично підтверджувати, що головний цикл працює.
- **FR-02.** Система повинна реєструвати присутність людини біля вітрини окремим типом події, без позначки про крадіжку.
- **FR-03.** Система повинна реєструвати зміну освітленості відносно базового рівня, коли зміна перевищує перевірений поріг.
- **FR-04.** Система повинна реєструвати короткий удар по корпусу окремо від тривалої зміни його положення.
- **FR-05.** Система повинна реєструвати зміну нахилу корпусу. Чи можна виявити повільне переміщення без зміни нахилу, потрібно перевірити; поки це не заявлена можливість.
- **FR-06.** Кожне повідомлення про подію повинно містити її тип і час від запуску пристрою.
- **FR-07.** Система повинна обробляти сигнали всіх трьох сенсорів у межах одного циклу роботи, не підміняючи один тип події іншим.
- **FR-08.** Система повинна відрізняти інформаційне повідомлення про присутність від тривоги за механічним впливом на корпус. Правила для зміни світла визначаються після перевірки показів.
- **FR-09.** Після перезапуску система повинна знову перейти в задокументований початковий стан і повідомити про нього через UART.

Пороги прототипу та стан перевірки наведено нижче. Реальні електричні параметри і короткі фізичні удари ще не перевірено.

## Компоненти

| Запланована модель | Інтерфейс | Для яких вимог | Розглянута альтернатива |
| --- | --- | --- | --- |
| PIR Motion Sensor у Wokwi | GPIO | FR-02, FR-07 | Кнопка дає керований цифровий сигнал, але не відтворює присутність людини. |
| Photoresistor Sensor у Wokwi | ADC | FR-03, FR-07 | Потенціометр зручний для перевірки ADC, але не відповідає сцені освітлення вітрини. |
| MPU-6050 у Wokwi | I²C | FR-04, FR-05, FR-07 | Кнопка або датчик нахилу не дають окремих даних для удару й зміни орієнтації. |

Параметри компонентів наведено в [hardware-components.md](hardware-components.md), підключення і ресурси плати в [pinout.md](pinout.md). Платформа STM32C031C6 продовжує ЛР1; окремого підтвердження погодження не збережено. Камери, SPI-flash і сервоприводу у складі цього PRD немає.

## План перевірки

| Вимоги | Перевірка у Wokwi | Що зберегти як доказ |
| --- | --- | --- |
| FR-01, FR-09 | Запустити та перезапустити прошивку. Звірити повідомлення UART і блимання LED. | Лог UART і запис екрана. |
| FR-02 | Подати сигнал присутності без впливу на інші сенсори. | Подію присутності без висновку про крадіжку. |
| FR-03 | Змінити освітлення вище й нижче підібраного порога. | Покази ADC та відповідні повідомлення. |
| FR-04, FR-05 | Окремо змоделювати удар і зміну нахилу. Перевірити, чи вони розрізняються. | Сирі покази й типи подій; обмеження моделі, якщо сценарій не відтворюється. |
| FR-06, FR-07, FR-08 | Подати сигнали одночасно та в різному порядку, зокрема лише присутність. | Журнал із часом, типами подій і станом тривоги. |

## Результати ЛР2

| Вимоги | Фактична перевірка | Стан |
| --- | --- | --- |
| FR-01, FR-09 | Кілька свіжих запусків: BOOT, SELFTEST, READY, DATA; reset logic у host tests | Startup і host reset перевірено; запис UART-команди r з latched alarm ще не збережено |
| FR-02 | PIR pulse та EVENT t=1411 type=PRESENCE alarm=0 | Перевірено у Wokwi |
| FR-03 | ADC 1001→4063, LIGHT_CHANGE; гістерезис у tests | Перевірено у Wokwi та host tests |
| FR-04 | Зміни Z до 0.05 і 1.6 g викликали SHOCK | Пороги перевірено; короткий удар і його тривалість ще не перевірено |
| FR-05 | X=0.6, Z=0.8 g, TILT через 500 мс, без SHOCK | Нахил перевірено; абсолютний повільний перенос не заявляється |
| FR-06 | EVENT містить t, type та alarm, UART декодовано з VCD | Перевірено |
| FR-07 | Одна прошивка читає всі три сенсори | Спільна робота перевірена; усі комбінації одночасних впливів не перевірені |
| FR-08 | PRESENCE/LIGHT_CHANGE alarm=0, SHOCK/TILT alarm=1; latch у tests | Перевірено |

Опитування 20 мс, telemetry 500 мс. LIGHT_CHANGE має поріг 600 counts і rearm <400. SHOCK має norm >1400 або <600 mg, rearm 900–1100. TILT має vector delta ≥400 mg, stable norm 800–1200 протягом 500 мс, rearm <250. Це початкові пороги, не фізично відкалібрована класифікація удару.

Докладні [реальні записи](captures/analysis.md) та [host tests/coverage](testing.md). Скриншоти додаються окремо.
